How I work: playbooks

The repeatable process behind my work. Open one to see the steps.

Microsoft 365 security hardening: five phases
  1. Assessment: review the tenant, domains, users, devices, licenses and current policies.
  2. Security design: find the gaps and design policies that fit the business and limit disruption.
  3. Implementation: deploy retention, MFA and security defaults, Conditional Access, anti-phishing, SPF/DKIM/DMARC, Identity Protection and auditing.
  4. Testing and validation: test sign-in, mail flow, Conditional Access (report-only first), device compliance and audit logs.
  5. Documentation and handover: document every control and recommend a quarterly security review. I work with a security-first, least-privilege mindset.
Compromised Microsoft 365 account
  1. Contain: reset the password, revoke active sessions and require MFA re-registration.
  2. Investigate: review Entra ID sign-in logs and the audit log for the first suspicious activity.
  3. Check persistence: look for new inbox rules, forwarding, delegated access and consented apps.
  4. Remediate: remove malicious rules and apps, and block the offending sign-in patterns.
  5. Verify: monitor sign-ins afterwards and confirm the suspicious access has stopped.
  6. Prevent: enforce MFA and Conditional Access, then document the incident and lessons learned.
Email migration to Microsoft 365
  1. Assess: inventory mailboxes, sizes, aliases, shared mailboxes and the source platform.
  2. Prepare: verify the domain, create users and licenses, and lower DNS TTLs.
  3. Pilot: migrate a small group first and fix issues before the main batch.
  4. Migrate: move mailboxes in batches, then update MX, SPF, DKIM and autodiscover records.
  5. Validate: compare item counts, test mail flow both ways and set up Outlook on devices.
  6. Hand over: support users, document the setup and decommission the old service.
Handling an unclear support request
  1. Clarify: ask when it started, what changed, who is affected and what the error says.
  2. Reproduce and check logs: confirm the issue and gather evidence before changing anything.
  3. Fix and verify: apply the smallest safe change, then confirm with the user.
  4. Document: record cause and fix in the ticket and update the knowledge article.
